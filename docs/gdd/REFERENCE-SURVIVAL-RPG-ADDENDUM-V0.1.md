# HNK-VERSE — SURVIVAL RPG REFERENCE ADDENDUM V0.1

**Status:** LOCKED REFERENCE INPUT / absorption classified below  
**Date:** 2026-09-22  
**Reference family:** Survival RPG series by Bew Games, with emphasis on Survival RPG: Open World Pixel  
**Phase:** GDD V0.1

## 1. Why this reference matters

Survival RPG adds a useful design layer that was not yet explicit enough in HNK-VERSE:

> **World interaction becomes more interesting when knowledge, materials and tools create new verbs.**

The official Survival RPG material emphasizes:

- open-world exploration;
- gathering/mining;
- crafting;
- house/tool/equipment construction;
- dungeons and castles;
- hidden objects and treasures;
- recipes discovered/unlocked during adventure;
- combat and hostile creatures;
- offline/mobile-friendly interaction.

Across the wider series, additional patterns include:

- puzzles;
- multiple biomes;
- time travel;
- ships/islands;
- spells;
- quests;
- equipment upgrades.

The HNK-VERSE does not copy Survival RPG content, pixel-art identity, narrative or proprietary expression.

It absorbs abstract design lessons.

## 2. Core design contribution

Survival RPG strengthens this HNK-VERSE formula:

KNOWLEDGE  
+ MATERIAL  
+ TOOL / WORLD CAPABILITY  
+ CONTEXT  
→ NEW ACTION  
→ WORLD ACCESS / TRANSFORMATION

This sits naturally beside the locked HNK-VERSE formula:

KNOWLEDGE  
→ PRACTICE  
→ CAPABILITY  
→ MANIFESTATION.

## 3. Mechanics classified for absorption

### A. Tool-gated world verbs — ABSORB

A tool should not merely provide +10 stats.

It should unlock or improve a concrete world verb.

Examples for future HNK-VERSE:

- Axe → cut/shape eligible wood.
- Pickaxe → mine eligible rock/ore.
- Hoe → prepare compatible soil.
- Container → carry liquids/materials.
- Fishing tool → fish in valid water context.
- Ladder/climbing tool → traverse compatible height/gap.
- Boat/vehicle → traverse compatible terrain.
- Detection/appraisal tool → reveal information.

General contract:

WORLD PROPERTY  
+ ACTOR KNOWLEDGE  
+ TOOL CAPABILITY  
+ PERMISSION  
→ ACTION AVAILABLE

### B. Crafting as progression infrastructure — ABSORB

Crafted objects should frequently enable future actions rather than being cosmetic inventory output.

Examples:

RESOURCE  
→ TOOL  
→ NEW RESOURCE ACCESS  
→ STRUCTURE  
→ NEW CAPABILITY.

This is fully compatible with D004 and D006.

### C. Recipes discovered through play — ABSORB

The player should not start with omniscient recipe knowledge.

Recipes/processes may be acquired through:

- exploration;
- CODEX-HNK;
- Agent teaching;
- institutions;
- experimentation;
- found documents;
- HNK-Idioma;
- prior successful transformation.

This maps to:

PERSONA KNOWLEDGE ≠ WORLD TRUTH.

### D. Rest as useful but non-punitive — ABSORB INTO ZERO

Survival RPG's optional sleeping/time-healing pattern reinforces the locked HNK-VERSE soft-needs philosophy.

ZERO Bed should:

- be optional for ordinary movement/exploration;
- recover the first Energy/Rest state;
- advance World Time through an authoritative Rest command;
- allow day transition when the time threshold is crossed.

It must not introduce mandatory sleep, hunger or punishment-heavy survival.

### E. Compact contextual mobile interaction — ABSORB

Survival RPG demonstrates the usefulness of:

- readable directional movement;
- small hotbar/quick items;
- one clear contextual action;
- simple object/tool switching;
- world-first presentation on small screens.

HNK-VERSE already has a quieter HUD philosophy; this reference reinforces a mobile interaction pattern where the world remains dominant.

### F. Exploration unlocks — ABSORB POST-ZERO

Future exploration can unlock:

- tools;
- materials;
- recipes;
- locations;
- shortcuts;
- maps;
- portal clues;
- Agent/institution access.

Exploration rewards should include capability, not only loot.

### G. Hidden objects / environmental puzzles — ABSORB POST-ZERO

This fits HNK-VERSE perception and epistemics particularly well.

Future puzzles may depend on:

PERCEPTION  
+ LANGUAGE  
+ KNOWLEDGE  
+ TOOL  
+ ENVIRONMENT.

The answer should be derivable from world state, not arbitrary pixel hunting.

### H. Mining / gathering chains — ABSORB POST-ZERO

Future gathering should evolve from the ZERO Wood node into a material ecology.

Potential chain:

DISCOVER SOURCE  
→ APPRAISE  
→ SELECT TOOL  
→ EXTRACT  
→ PROCESS  
→ STORE / USE  
→ WORLD CONSEQUENCE.

### I. Biomes and traversal — ABSORB POST-ZERO

Different regions should create different:

- materials;
- hazards;
- ecology;
- tools;
- movement requirements;
- knowledge opportunities.

Biome difference should be systemic, not palette-swapping only.

### J. Dungeons / caves / ruins — ABSORB POST-ZERO

Already compatible with D006 and HNK: World of Dungeons.

Survival RPG reinforces:

HUB / HOME  
→ PREPARE  
→ TRAVEL  
→ EXPLORE  
→ SOLVE / GATHER / FIGHT  
→ RETURN  
→ PROCESS / UPGRADE.

### K. Time-sensitive world behavior — ABSORB POST-ZERO

Community-documented Survival RPG behavior includes time-dependent encounters.

HNK-VERSE can later use World Time to affect:

- Agent schedules;
- creature behavior;
- visibility;
- resource conditions;
- anomaly conditions;
- institutions;
- events.

ZERO only proves day/time and Rest; it does not add night monsters.

### L. Farming and water/tool chains — ABSORB POST-ZERO

Future agriculture should use actual capabilities and resources rather than one-click farm plots.

Candidate example:

WATER SOURCE  
+ CONTAINER  
+ SOIL  
+ HOE / TOOL  
+ SEED  
+ TIME  
+ CARE  
→ CROP.

This remains post-ZERO.

## 4. ZERO absorption decisions

Survival RPG contributes four concrete improvements to the current ZERO design without increasing its content count.

### 4.1 Bed becomes a real World verb

The already-locked Bed/Rest entity must support:

REST  
→ validate Bed + access  
→ recover Energy/Rest  
→ advance World Time  
→ emit authoritative event(s)  
→ persist.

### 4.2 Workbench becomes the first Tool/Process context

The Workbench is not just a craft menu.

It is a World fixture whose capability permits the Wooden Box process once knowledge and resources are valid.

### 4.3 Wooden Box remains functional

The Wooden Box validates the Survival RPG lesson:

> created objects should do something.

It remains the first:

- storage object;
- persistent creation;
- owned placed entity;
- evidence of world history.

### 4.4 Recipe/process visibility is knowledge-driven

The Wooden Box process should not be fully actionable before the Persona acquires the required practical knowledge.

The UI may show:

UNKNOWN / LOCKED PROCESS

then later:

KNOWN / ACTIONABLE PROCESS

without relying on an arbitrary player level.

## 6. HNK-VERSE differentiation

HNK-VERSE goes deeper than the Survival RPG reference in four areas.

### Knowledge provenance

A recipe/process can preserve how the Persona learned it.

### Evidence-backed mastery

Using a tool/process can create Skill Evidence rather than generic XP only.

### Persistent Agents

Agents can remember discovery, teaching, creation and exchange.

### Metaphysical/symbolic separation

A physical action may have HNK correspondences without collapsing game effects into proof of metaphysical claims.

## 7. Future Tool Capability model

Candidate schema concept:

TOOL_DEFINITION:

- stable ID;
- material;
- capabilities[];
- compatibleWorldProperties[];
- minimumSkill?;
- knowledgeRequirements[];
- durability model?;
- energy/resource cost?;
- provenance.

Example capability:

CUT_WOOD

requires:

- target.materialClass = WOOD;
- target.cuttable = true;
- actor permitted;
- actor tool has CUT_WOOD;
- knowledge gate satisfied.

This should be implemented after ZERO unless required by a later vertical slice.

## 8. Future environmental progression

Recommended post-ZERO progression pattern:

HOME / LAND  
→ HAND GATHERING  
→ BASIC TOOL  
→ NEW MATERIAL  
→ ADVANCED TOOL  
→ NEW TERRAIN  
→ STRUCTURE / TRANSPORT  
→ EXPEDITION  
→ DUNGEON / REGION  
→ NEW KNOWLEDGE / CAPABILITY.

The player becomes more capable because their knowledge, tools and world relationships expand.

## 9. Avoided baggage

Do not absorb:

- pixel-art identity as a constraint;
- arbitrary tool gates with no world logic;
- punitive survival meters;
- recipe-list bloat;
- loot-only progression;
- automatic combat as the core identity;
- monetization structures;
- content grind for its own sake.

## 10. GDD impact

### ZERO Interaction + Event Contract
Add explicit Rest semantics and Workbench capability semantics.

### ZERO Persistence
Persist Energy/Rest and World Time across Rest/day transition.

### Post-ZERO backlog
Add a Tool Capability + Environmental Progression epic after ZERO is green.

### Visual/UX
Preserve simple mobile contextual interaction and compact quick-access tools without increasing default HUD density.

## 11. Locked reference conclusion

Survival RPG is accepted as an HNK-VERSE **mechanical reference** for:

- functional crafting;
- tool-gated world interaction;
- discovery-driven processes;
- exploration capability unlocks;
- light/non-punitive Rest;
- compact mobile action UX;
- material/traversal progression.

Its major world-expansion mechanics are **post-ZERO**.
