# Verse SDK v0.1 + HNK-VERSE ZERO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the smallest contract-first Verse SDK required to make the HNK-VERSE ZERO journey exercise real Hub/A/B capability negotiation, isolated Verse state, projection/translation, correlated Chronicle events, and the Personal Space creator publish loop.

**Architecture:** Extend the existing TypeScript/pnpm monorepo rather than replacing its current ZERO runtime. Universal protocol types stay in `@hnk-verse/contracts`; executable SDK boundary logic lives in a new `@hnk-verse/sdk`; Chronicle remains authoritative for runtime event projection; existing `world`/`domain` ZERO code is adapted behind the SDK incrementally. The first runtime adapter is in-process TypeScript, but all public SDK interfaces remain transport-neutral and HNK-KODE-ready.

**Tech Stack:** Node >=22, pnpm 10.17.1, TypeScript 5.8.3, ES modules, existing script-based TDD/check harness.

**Spec:** `docs/superpowers/specs/2026-09-27-verse-sdk-v0.1-design.md`

## Global Constraints

- Contract-first + runtime-agnostic.
- Minimal Core + optional modules.
- `PLATFORM OWNS THE BORDER → VERSE OWNS ITS REALITY → CONTRACT GOVERNS THE CONNECTION`.
- `ABSENT CAPABILITY = UNSUPPORTED BY DEFAULT`.
- `HNK-ID != HNK-Address`.
- Identity continuity does not imply state or permission continuity.
- Interop outcomes are exactly `REJECT | REFERENCE | PROJECT | TRANSLATE | TRANSFER | CLONE`.
- `RUNTIME EVENT != CODEX-HNK CANON`.
- HNK-KODE is not an implementation dependency of ZERO.
- Preserve existing ZERO behavior while moving cross-Verse concerns behind the SDK.

## Review Focus

- Missing/unknown capability must return `UNSUPPORTED_CAPABILITY`, never implicit acceptance — pinned in Task 2.
- A compatible identity with incompatible contract versions must still be rejected before Verse entry — pinned in Task 2.
- A rejected gameplay transfer must coexist with an independently accepted projection in the same transition — pinned in Task 4.
- A target failure after source preparation must never emit `TransitionCompleted` and must leave a valid presence — pinned in Task 4.
- Draft edits after publish must not mutate the immutable published Personal Space version — pinned in Task 7.
