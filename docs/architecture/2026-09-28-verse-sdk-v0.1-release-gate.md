# Verse SDK v0.1 — Release Gate

Status target: **v0.1 integration candidate**.

## Public SDK surface

`@hnk-verse/sdk` exposes:

- capability negotiation and ZERO manifests;
- Chronicle boundary event construction and causal-chain validation;
- platform-owned transition coordination;
- six-outcome Interop Engine (`REJECT | REFERENCE | PROJECT | TRANSLATE | TRANSFER | CLONE`);
- lifecycle runtime with guarded state transitions.

## ZERO integrated proof

The SDK test chain includes a Hub → Experience A → Hub → Experience B fixture. It proves target capability negotiation, cross-context interop/projection and lifecycle continuity through the public SDK surface.

## Release gate

A candidate is green only when all of the following pass from a frozen lockfile:

1. `pnpm install --frozen-lockfile`
2. `pnpm typecheck`
3. `pnpm test:verse-sdk`
4. all legacy ZERO checks through root `pnpm test`
5. `pnpm web:build`

The canonical aggregate command is `pnpm check` after the frozen install.

## Architecture invariants

- `PLATFORM OWNS THE BORDER → VERSE OWNS ITS REALITY → CONTRACT GOVERNS THE CONNECTION`.
- `ABSENT CAPABILITY = UNSUPPORTED BY DEFAULT`.
- Identity continuity does not imply state or permission continuity.
- Runtime Chronicle events do not promote themselves to CODEX-HNK canon.
- Interop results preserve provenance.

## CI

`.github/workflows/verse-sdk-release-gate.yml` runs the reproducible install and full `pnpm check` for SDK-relevant pull requests and pushes to `main`.
