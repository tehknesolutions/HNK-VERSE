## Purpose

## Source-backed findings

TKN-OS README defines TKN-OS as the institutional, technical and computable center of Tehkné for organizing, relating, preserving and reusing knowledge from projects, products, research, experiments, code, design, decisions, errors, assets and operations.

It identifies TEHKNÉ CANON, GIP, Knowledge, Registry, LAB, Archaeology, Evidence & Provenance, Assets and Intelligence as integrated concerns.

The README establishes:
- Planned Distribution → Progressive Manifestation.
- Knowledge lifecycle: RAW → OBSERVED → EXPERIMENTAL → REVIEWED → APPROVED → CANON.
- Historical states: REJECTED, SUPERSEDED, DEPRECATED, ARCHIVED.
- Rebuildability: derived indexes, embeddings, projections, caches, searches and graphs must be reconstructible from authoritative sources.

TKN-OS Authority Model v0.1 explicitly states that TKN-OS is the Tehkné ecosystem meta-center, not a universal semantic owner. Authority is scoped: ECOSYSTEM REGISTRY AUTHORITY ≠ DOMAIN ROOT CANON.

It defines authority levels:
ROOT_CANON, DOMAIN_CANON, PRODUCT_CANON, IMPLEMENTATION_AUTHORITY, PROJECTION, EVIDENCE_SOURCE and HISTORICAL_SOURCE.

Canonical promotion:
DISCOVERED → CLASSIFIED → CANDIDATE → REVIEWED → APPROVED → CANONICAL / RELEASED.

Evidence progression:
UNVERIFIED → OBSERVED → TESTED → VALIDATED → CERTIFIED.

The No-Shadow-Truth invariant says that when another project owns canonical state, TKN-OS should keep a typed reference/evidence rather than a second independently editable copy.

The model also requires typed lineage semantics instead of generic related_to edges.

## HNK-VERSE consequences

Domain may consume stable concepts such as provenance, evidence, typed lineage, knowledge lifecycle, rebuildability and governance decisions. Domain must not silently promote project-specific Tehkné implementation details into universal HNK reality.

Verse may adopt GIP/process contracts when explicitly part of that Verse/product.

Kodan may use Tehkné workflows as manifestation methodology. GIP is therefore a process layer, not WorldState authority.

Chronicle should preserve provenance for decisions, transformations, experiments, validation and implementation events when those events affect Verse reality.

Cognition may consume governed knowledge/evidence while distinguishing source truth, observed evidence, derived interpretation, generated candidate and retained memory.

## GIP → HNK-VERSE derived mapping

This mapping is a design derivation, not an existing TKN-OS runtime contract:

- Architecture → Domain/Verse design.

- Commit checkpoint → versioned implementation/provenance checkpoint.

Any adoption must be versioned and provenance-linked.
