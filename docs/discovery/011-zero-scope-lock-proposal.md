# DISCOVERY 011 — ZERO SCOPE LOCK

**Status:** PROPOSAL — awaiting Creator lock  
**Date:** 2026-09-22  
**Depends on:** DISCOVERY 002–010 + LEGACY CONVERGENCE AUDIT V2

## 1. Purpose

ZERO is the first complete playable proof of HNK-VERSE.

It is not a demo of isolated mechanics and it is not a miniature version of every future feature.

ZERO exists to prove the smallest end-to-end experience in which the product thesis is already true:

> **What the player learns, expresses, practices and creates becomes persistent change in a living Personal Verse.**

## 2. ZERO thesis

The first playable experience must prove:

CODEX-HNK — SABER  
↓  
HNK-IDIOMA — EXPRESSAR  
↓  
HNK-VERSE — MANIFESTAR  
↓  
WORLD CHANGE  
↓  
EXPERIENCE  
↓  
RECORD  
↓  
PERSISTENCE

Operational loop:

DISCOVER
→ LEARN
→ NAME
→ PRACTICE
→ GATHER
→ CREATE
→ PLACE / USE
→ TRANSFORM WORLD
→ INTERACT
→ OBSERVE CONSEQUENCE
→ RECORD
→ RETURN LATER
→ SEE THAT THE WORLD REMEMBERS

## 3. ZERO is Malkuth

The first executable world layer is **Malkuth**.

ZERO does not attempt to implement the entire Tree.

The Sephirotic meta-architecture already exists above the runtime, but ZERO only needs enough Malkuth content and references to prove:

- embodiment;
- world;
- matter;
- action;
- ownership;
- creation;
- persistence;
- relationship;
- knowledge;
- manifestation.

Specific canonical Malkuth content must consume approved CODEX-HNK sources rather than be invented in implementation.

## 4. Player promise

Within the first short session, the player should be able to understand:

> **"Eu aprendo coisas aqui, uso o que aprendi e o meu mundo muda."**

After leaving and returning, the player should also understand:

> **"O mundo lembra do que eu fiz."**

## 5. ZERO world

ZERO contains exactly one playable Personal Verse context:

- 1 HNK Identity;
- 1 primary Personal Verse;
- 1 World Instance;
- 1 Malkuth starting area;
- 1 Land;
- 1 Home;
- 1 Avatar;
- 1 persistent Agent;
- a minimal surrounding playable area.

Architecture may support future multiple Worlds/Avatars, but ZERO UI does not need them.

## 6. ZERO world hierarchy

For ZERO:

PERSONAL_VERSE
→ WORLD_INSTANCE
→ MALKUTH_AREA
→ LAND
→ HOME
→ OBJECTS / RESOURCE NODES / AGENT / AVATAR

The implementation should already use stable IDs and provenance consistent with future expansion.

## 7. ZERO visual target

Primary presentation:

**HD 2D / 2.5D ISOMETRIC OR NEAR-ISOMETRIC**

ZERO requires:

- readable Home/Land;
- clear walkable space;
- readable avatar;
- readable Agent;
- functional object silhouettes;
- visible world-state change;
- day/time visual change;
- desktop usability;
- mobile usability.

Visual richness is secondary to reliable interaction and readable world state.

## 8. ZERO player embodiment

One Avatar proves:

- stable ID;
- appearance;
- position;
- movement;
- interaction;
- inventory;
- one soft life state;
- one knowledge state;
- one skill state;
- one relationship;

ZERO does not require multiple avatars or character-class selection.

## 9. ZERO time

One World Time model proves:

- accelerated day cycle;
- current world timestamp;
- one day transition;
- one visual time change;
- persistence.

Real-world timestamps are separately recorded for provenance.

ZERO does not require seasons.

## 10. ZERO Home

HOME is the life anchor.

It must support at least:

- spawn/return;
- storage;
- one functional object;
- one editable placement zone;
- one persistent created object;
- one Agent visit/presence or nearby interaction;
- visual evidence of player history.

HOME must already feel like a place rather than a menu.

## 11. ZERO life state

Only one soft life state is required to prove the Life Model.

Recommended first candidate:

**ENERGY / REST**

It may:

- change gradually;
- affect one optional action quality or feedback;
- recover through one functional Home object/action.

It must not create a punishment-heavy survival loop.

## 12. ZERO resource

Exactly one primary gatherable resource is required.

The resource must have:

- stable definition;
- one meaningful property;
- world location/source;
- gather action;
- ownership;
- inventory representation;
- provenance event.

The final canonical resource should be chosen from approved HNK/Malkuth context during GDD/content authoring.

ZERO Discovery does not invent its canonical name.

## 13. ZERO knowledge

Exactly one primary knowledge unit is required.

It should connect the resource to a possible transformation.

Knowledge may be acquired through one of:

- CODEX-HNK entry;
- Agent teaching;
- object inspection;
- discovery;
- contextual practice.

The Persona must have a distinct knowledge state.

CODEX CANON ≠ PERSONA DISCOVERED KNOWLEDGE

## 14. ZERO HNK-Idioma

Exactly one approved HNK-Idioma element must appear in context.

It must not be decorative only.

It should contribute to one of:

- recognition;
- naming;
- understanding;
- action;
- interaction;
- symbolic identification.

The final element must be imported from approved HNK-Idioma canon.

HNK-VERSE must not generate a new HNK word merely to fill ZERO.

## 15. ZERO perception

Example pattern:

OBJECT / RESOURCE EXISTS
→ PLAYER CAN SEE BASE FORM
→ KNOWLEDGE / LANGUAGE / APPRAISAL
→ ADDITIONAL VALID INFORMATION BECOMES VISIBLE

The underlying World State remains unchanged by the UI reveal.

KNOWLEDGE

One Agent/Mentor reaction should be able to reference the demonstrated state.

## 17. ZERO creation

Minimum:

RESOURCE

- ownership;

## 20. ZERO inventory and ownership

- carried inventory;
- Home storage or one storage object;
- ownership state.

One authorized resource/item transfer should be possible.

## 21. ZERO economy

ZERO economy is intentionally microscopic.

It requires only one of:

- gift;
- barter;
- simple trade;
- simple service exchange.

Recommended proof:

PLAYER
→ transfers one owned item/resource to Agent
→ Agent accepts/refuses according to rule
→ ownership changes if accepted
→ relationship/history changes
→ event persists

No currency is required.

## 22. ZERO Agent

Exactly one persistent Agent is required.

Minimum contract:

- name/identity;
- one location/home context;
- one goal;
- one relationship vector with player;
- one knowledge/belief;
- one episodic memory;
- one permitted autonomous action;
- one dialogue/interaction surface;
- one later memory-based reaction;
- persistent history across logout/login.

The cognitive implementation may initially be deterministic/hybrid.

ZERO does not require an always-on LLM.

## 23. ZERO Agent epistemics

The Agent must prove one distinction between:

WORLD TRUTH
and
AGENT KNOWLEDGE / BELIEF

Agent speech must not automatically become runtime truth or HNK canon.

At least one Agent statement/teaching record should preserve source/provenance.

## 24. ZERO relationship

One player-Agent relationship vector is enough.

- familiarity;
- trust;
- history.

One action should modify relationship history.

## 25. ZERO Agent autonomy

→ DOMAIN COMMAND

## 26. ZERO Chronicle

## 38. ZERO 10-minute experience

Candidate playable sequence:

1. Player enters their Personal Verse.
2. Avatar appears at HOME in Malkuth.
3. Player meets the persistent Agent.
4. Player inspects one nearby resource/object.
5. A Codex/HNK-Idioma-linked discovery reveals useful information.
6. Player gathers one resource.
7. Player performs one practice/action.
8. The attempt produces skill evidence.
9. Player creates one functional object.
10. Player previews and places it at HOME/LAND.
11. World State visibly changes.
12. Agent notices/responds using relationship/memory state.
13. Player gives/trades one small resource/object or completes one simple exchange.
14. Chronicle records the discovery/creation/interaction.
15. Player ends/leaves the session.
16. Player returns.
17. Created object, knowledge, relationship, Agent memory and Chronicle remain.

The precise narrative/content should be authored during GDD after canonical source selection.

## 39. ZERO success criteria

ZERO is successful only if all of the following are true:

### Product
A new user can understand that learning changes what they can do and what they do changes the persistent world.

### World
One world-state mutation is authoritative and persistent.

### Knowledge
One canonical knowledge/language reference affects gameplay.

### Mastery
One practiced capability is backed by event evidence.

### Agent
One persistent Agent remembers a meaningful interaction.

### Social/Economy
One authorized transfer changes ownership and social history.

### Creator
One entity is created/placed through validated world mutation.

### Epistemics
World truth remains distinct from perception/Agent belief/interpretation.

### Persistence
All required states restore correctly after logout/login.

### Visual
The loop is readable at actual gameplay scale.

### Responsive
The core loop works on desktop and mobile.

### Governance
No game action silently grants HNK canonical authority or official Taijifu graduation.

## 40. Release blockers

ZERO cannot be considered complete if any of these remain:

- renderer is the only source of world state;
- placed objects disappear after reload;
- Agent identity resets;
- Agent memory is only transient chat history;
- CODEX/HNK-Idioma content is duplicated without authority/version reference;
- skill progression occurs only by arbitrary XP;
- ownership transfer can duplicate resources;
- Agent can bypass domain permissions;
- interpretation is stored as evidence/canon automatically;
- mobile core loop is unusable;
- asset status/provenance is unknown;
- ZERO requires manual developer database fixes to complete the intended loop.

After ZERO is green, expansion should add breadth to proven systems instead of creating parallel replacements.

Examples:

- 1 Agent → population;

- 1 world → multiverse traversal.

## 45. Candidate ZERO lock decisions

1. ZERO is the first complete end-to-end proof of HNK-VERSE, not a feature showcase.
2. ZERO is located in the first executable Malkuth layer.
3. The Personal Verse exists from first login.
4. ZERO uses one World Instance, one Land, one Home, one Avatar and one persistent Agent.
5. The golden loop is discover → learn/name → practice → gather/create → place/use → world change → social consequence → record → persist.
6. One versioned CODEX-HNK reference and one approved HNK-Idioma element must affect gameplay.
7. One perception gate must prove that Persona knowledge affects visible/actionable information.
8. One evidence-backed Skill must progress from an authoritative practice event.
9. One resource and one functional created object are sufficient.
10. One persistent placement proves "the world is playable matter."
11. ZERO includes one small ownership transfer/gift/trade proof without requiring currency.
12. One Agent must preserve identity, memory, relationship and one autonomous authorized action.
13. One Chronicle/reflection surface is required but remains downstream of the Event Ledger.
14. All consequential actions produce authoritative domain events.
15. Persistence across logout/login is a release blocker.
16. ZERO preserves the full Lucidity separation even with minimal UI.
17. Web/PWA desktop and mobile are both required for the core loop.
18. ZERO deliberately excludes multiplayer, portals, cities, full combat, full Taijifu, full Creator Studio, creature systems and multiple Worlds unless needed later by a proven blocker.
19. Deterministic fixtures and E2E validation are required before human visual/device QA.
20. Future expansion extends proven systems rather than replacing ZERO architecture.
