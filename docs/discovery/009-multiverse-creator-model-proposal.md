# DISCOVERY 009 — MULTIVERSE + CREATOR MODEL

**Status:** PROPOSAL — awaiting Creator lock  
**Date:** 2026-09-22  
**Depends on:** DISCOVERY 002–008 + LEGACY CONVERGENCE AUDIT V2 + CREATOR SYSTEM LEGACY ADDENDUM

## 1. Design question

How are Personal Verses, Worlds, world instances, templates, portals, shared spaces and creator authority represented inside HNK-VERSE?

This model defines:

- Personal Verse ontology;
- World vs World Instance vs World Template;
- multiverse topology;
- portals and traversal;
- shared/intersection spaces;
- world forks and provenance;
- creator authority;
- world laws;
- creator tooling;
- entity graphs;
- spatial authoring;
- behaviors/automation;
- AI-assisted creation;
- publication;
- canonical boundaries;
- world packages;
- interoperability;
- safety and rollback;
- progression from inhabitant to advanced creator.

## 2. Core principle

> **THE PERSONAL VERSE IS FOUNDATIONAL FROM THE BEGINNING. PROGRESSION DOES NOT AWARD A VERSE; IT EXPANDS THE USER'S ACCESS, UNDERSTANDING AND CREATIVE AUTHORITY WITHIN IT.**

Therefore:

PERSONAL VERSE ≠ ENDGAME REWARD

WORLD CREATOR ≠ HNK CANON CREATOR

VERSE CREATOR ≠ OWNER OF HNK CANON

CREATOR AUTHORITY ≠ CANONICAL AUTHORITY

A Personal Verse is the user's persistent universe container.

It may contain:

- multiple Worlds;
- world history;
- avatars;
- Agents;
- creatures;
- institutions;
- lands;
- properties;
- knowledge;
- language state;
- relationships;
- creator projects;
- portals;
- symbolic/metaphysical correspondences;
- governance;
- provenance;
- Chronicle.

The Personal Verse exists even when only a small Malkuth manifestation is initially accessible.

## 5. World Template vs World Instance

### WORLD TEMPLATE

Defines reusable structure:

- world rules;
- starting geography;
- systems;
- content packs;
- allowed entities;
- progression;
- visual language;
- creator constraints;
- portal policy.

### WORLD INSTANCE

A persistent instantiated world with:

- unique identity;
- history;
- inhabitants;
- state;
- modifications;
- events;
- ownership;
- relationships;
- provenance.

Therefore:

WORLD TEMPLATE ≠ WORLD INSTANCE

Multiple World Instances may derive from the same template and diverge historically.

## 6. World identity and provenance

Every persistent World Instance requires:

- stable world ID;
- template/version origin;
- creator/authority provenance;
- creation event;
- parent/fork source if applicable;
- rule-set version;
- content-pack versions;
- migration history;
- current state version.

A world must be able to explain where it came from.

## 7. World rules

Rule domains may include:

- combat;
- magic;

HNK deep meta-architecture remains beneath them.

## 8. Local phenomena

D004/AFTERWORLD established:

GLOBAL WORLD_RULESET + LOCAL PHENOMENON_RULESET

Therefore a world may have stable global laws while locations/events temporarily or permanently alter local conditions.

Examples may affect:

- time;
- geometry;
- gravity;
- matter;
- signals;
- spiritual/metaphysical pressure where HNK canon defines it.

Local anomaly does not silently rewrite the whole world.

## 11. World transfer

When an entity crosses worlds:

SOURCE ENTITY
→ EXPORT CHECK
→ TRANSFER ENVELOPE
→ DESTINATION IMPORT CHECK
→ CAPABILITY TRANSLATION
→ MATERIALIZATION
→ EVENT LEDGER

The destination world may:

- preserve capability;
- constrain capability;
- translate capability;
- suspend capability;
- reject transfer.

This prevents one world's rules from trivially breaking another.

## 14. World forks

A World may intentionally fork.

Fork creates:

NEW WORLD ID
+ PARENT WORLD REF
+ FORK EVENT
+ SNAPSHOT / TEMPLATE VERSION
+ NEW HISTORY

After the fork:

PARENT HISTORY ≠ CHILD HISTORY

Changes do not silently synchronize unless a separate merge/sync system is explicitly designed.

## 15. Agent and creature forks

Cross-world copying must not accidentally duplicate persistent individuals.

Candidate choices:

### TRANSFER
Same persistent identity moves.

### PROJECTION
Temporary representation tied to original identity.

### FORK
A new identity is created with explicit provenance.

### TEMPLATE SPAWN
A new individual is created from a reusable archetype/template.

The operation must be explicit.

WORLD AUTHORITY

## 45. Candidate lock decisions

1. Personal Verse exists from the beginning; progression expands access and creator authority rather than awarding a Verse at endgame.
2. World Template and persistent World Instance are separate concepts.
3. Every World Instance has stable identity, versioned rules and provenance.
4. Multiverse topology is represented as a graph of Worlds, portals, intersections and forks.
5. Portal traversal is an authoritative domain operation with import/export rules.
6. Cross-world transfer may preserve, constrain, translate, suspend or reject capabilities according to destination rules.
7. Inter-Verse multiplayer uses explicit controlled intersections.
8. World forks create new identities and divergent histories with explicit provenance.
9. Agent/creature transfer, projection, fork and template-spawn are distinct operations.
10. Creator progression expands authority through the D004 ladder from placement to Verse building.
11. Creator actions use a permission/knowledge/skill/resource/world-rule authority matrix.
12. The future Creator architecture follows definitions → entities → relationships → spatial bindings → behaviors → commands → events → World State.
13. Entity identity, spatial binding and renderer representation remain distinct.
14. Ports/interfaces provide data-driven modular compatibility.
15. Behaviors and automation execute through normal domain commands.
16. Creator AI produces structured proposals/plans and does not directly mutate World State without delegated authority.
17. UGC requires provenance and versioned publication state.
18. Player/generated content is never HNK canon automatically.
19. Initial extensibility favors declarative/sandboxed systems over unrestricted executable mods.
20. Official/canonical Worlds may enforce stricter edit/canon locks than user-created Worlds.
21. World/Verse/Platform/Canonical authority remain distinct.
22. Creation history is versioned and recoverable.
23. Collaborative creation uses explicit roles and provenance.
24. World migrations preserve identity/history/ownership as far as possible.
25. "Verse Creator" means advanced product/worldmaking authority within a Personal Verse, not authority over HNK itself.
