# DISCOVERY 006 — RPG + MASTERY MODEL LOCK

**Status:** LOCKED  
**Date:** 2026-09-22  
**Authority:** Creator-approved HNK-VERSE product canon  
**Depends on:** DISCOVERY 002–005 + LEGACY CONVERGENCE AUDIT V2

## 1. Design question

How does a player become more capable inside HNK-VERSE without collapsing progression into levels, fixed classes, combat power or arbitrary XP?

The RPG + Mastery Model defines capability progression, skills, professions, knowledge requirements, HNK-Idioma integration, evidence of practice, mentors, quests, combat, magic/metaphysical capabilities, alchemy, technology, exploration, dungeons, reputation and Sephirotic meta-progression.

## 2. Core principle

> **KNOWLEDGE UNLOCKS POSSIBILITY. PRACTICE PRODUCES CAPABILITY. EVIDENCE SUSTAINS MASTERY. XP SUMMARIZES PROGRESS — IT DOES NOT CREATE MASTERY.**

KNOWLEDGE ≠ SKILL

EXPOSURE ≠ UNDERSTANDING

UNDERSTANDING ≠ EXECUTION

EXECUTION ≠ MASTERY

XP ≠ AUTHORITY

## 3. No mandatory starting class

HNK-VERSE does not require the player to select a permanent class such as warrior, mage, farmer or artisan at character creation.

Identity emerges through action:

ACTIVITY → PRACTICE → EVIDENCE → SKILL → MASTERY CLUSTER → PROFESSION / ROLE

A player may combine domains. Examples include builder + researcher, martial practitioner + linguist, alchemist + farmer, explorer + creature handler, engineer + merchant or scholar + governor.

The system should support specialization without permanently forbidding cross-training.

## 4. Progression layers

### Knowledge progression

What the Persona has encountered, perceived, learned, supported or reproduced.

Derived from Crônicas:

REPORTED → OBSERVED → HYPOTHESIZED → SUPPORTED → REPRODUCED

with possible CONTRADICTED / RETIRED states.

Knowledge affects interpretation and available actions, but does not by itself prove execution skill.

### Language progression

What the Persona can recognize, understand, name, read or express through HNK-Idioma.

HNK-VERSE consumes versioned HNK-Idioma canon. The game must not invent linguistic canon.

Language capability may function as a perception/action gate where canonically defined.

### Skill progression

What an avatar can repeatedly execute.

Skill requires relevant world events and evidence, not only a numeric purchase.

### Profession progression

A profession emerges from connected mastery clusters.

Professions are descriptive/executable identities, not mandatory exclusive classes.

### Relationship/Reputation progression

Trust, respect, history, obligations and social reputation may unlock teaching, cooperation, disclosure, trade or institutional access.

### Authority progression

Some progression grants local authority such as household permissions, guild/institution roles, settlement responsibility, governance and creator/world permissions.

Authority remains separate from HNK canonical authority.

### Manifestation progression

The player's increasing capacity to produce persistent world change through knowledge, language, practice, tools, resources, relationships and permissions.

## 5. General mastery ladder

Taijifu Masters already proves a rigorous martial-specific ladder:

SEEN → RECOGNIZED → UNDERSTOOD → DEFENDED → REPRODUCED → ADAPTED → MASTERED

HNK-VERSE should generalize the principle but not force identical labels on every skill domain.

Universal semantic phases:

ENCOUNTER → RECOGNIZE → UNDERSTAND → PRACTICE → REPRODUCE → APPLY → ADAPT → MASTER

A specific discipline may omit or rename phases.

### Mastery invariants

- encountering content never grants mastery;
- reading a Codex entry may unlock understanding but not execution;
- repetition without correct context need not advance mastery;
- independent reproduction is stronger evidence than guided reproduction;
- adaptation demonstrates deeper mastery than rote repetition;
- mastery may decay in readiness/performance without deleting historical achievement if a world/domain chooses to model decay.

## 6. Evidence-backed skill progression

A skill progression record should be able to reference actual runtime evidence.

SKILL_EVIDENCE = EVENT_REFS + CONTEXT + RESULT + QUALITY + INDEPENDENCE + REPEATABILITY

Examples:

- build a valid structure;
- correctly identify a material;
- execute a Taijifu defense;
- prepare a working alchemical process;
- communicate successfully using HNK-Idioma;
- navigate a route without assistance;
- repair a machine;
- cultivate and harvest a crop;
- resolve an investigation through independent evidence;
- negotiate a trade;
- command an Agent through authorized rules.

XP may be awarded from these events, but XP is a projection over evidence rather than the only source of truth.

## 7. XP model

XP remains useful for feedback, pacing, milestone readability, UI summaries and optional content gates.

But:

XP TOTAL ≠ MASTERY PROOF

Candidate XP families may exist by domain:

- Knowledge XP;
- Exploration XP;
- Creation XP;
- Social XP;
- Martial XP;
- Profession XP;
- Civilization XP.

A world may expose different XP surfaces.

No XP family may silently grant official Taijifu graduation or HNK canonical authority.

## 8. Attributes

Attributes may summarize broad capability tendencies, but must not become the sole authority for skills.

ATTRIBUTE → modifies opportunity/performance

SKILL → proves domain capability

KNOWLEDGE → informs valid action

EQUIPMENT / TOOL → changes execution context

WORLD RULE → constrains all of the above

Specific canonical HNK attribute names and values should be imported only from approved HNK sources, not invented by this Discovery document.

## 9. Professions

Professions are mastery clusters with meaningful world affordances.

Candidate families include gathering, agriculture, construction, crafting, alchemy, engineering, research, language, teaching, commerce, exploration, navigation, martial practice, creature handling, medicine/support within game fiction, governance and creator/world authoring.

A profession may provide institutional access, tools, recipes/processes, contracts, reputation, economic opportunities, mentor relationships and advanced capabilities.

## 10. Mentors and Masters

Mentors should not behave as simple skill shops.

A Mentor/Master can observe performance, explain, demonstrate, assign practice, create trials, evaluate evidence, unlock advanced study and disclose knowledge according to relationship and authority.

Taijifu Masters provides direct internal precedent for executable master trials.

Mentorship loop:

MEET → GAIN ACCESS → OBSERVE → TRAIN → RECEIVE FEEDBACK → PROVE → ADVANCE

Some knowledge may also be self-discovered without a mentor.

## 11. Quests as world contracts

Quests should represent structured objectives inside the world rather than detached checklist UI.

Candidate categories:

- exploration;
- investigation;
- gathering;
- crafting;
- construction;
- social;
- teaching;
- training;
- combat;
- dungeon/expedition;
- creature/ecology;
- trade;
- institution;
- governance;
- Codex discovery;
- HNK-Idioma usage;
- practice/reflection;
- world-creation.

A quest may originate from an Agent, human player, institution, settlement, world event, Codex discovery, local anomaly or player-authored content.

Quest completion should be derived from authoritative events where possible.

## 12. Adventure and dungeon loop

HNK: World of Dungeons provides the internal prototype:

HUB → CONTRACT → PREPARE → GATE / JOURNEY → DUNGEON → CONFRONT → GATHER / DISCOVER → RETURN → REPORT / REWARD → MEMORY

The HNK-VERSE version expands it:

HOME / CITY → PREPARE → ACCEPT PURPOSE → TRAVEL → PERCEIVE → EXPLORE → SOLVE / FIGHT / GATHER → SURVIVE → RETURN → PROCESS → RECORD → WORLD CONSEQUENCE

Dungeons need not all be underground combat maps. They may be ruins, laboratories, anomalous zones, caves, forests, towers, dreams/symbolic spaces when canonically allowed, portals or procedurally generated expedition spaces.

## 13. Combat philosophy

Combat is a first-class system but not the universal center of progression.

HNK-VERSE should support direct readable action combat appropriate to its chosen renderer/perspective.

Combat truth is independent from presentation assets:

GAMEPLAY STATE → COMBAT STATE → PRESENTATION MAP → ANIMATION / VFX

Taijifu Masters and Alakazam Strangeverse provide internal evidence for this separation.

Candidate combat capabilities include movement, positioning, guard, dodge, attack, defense, parry, grappling, disarm, tool/weapon use, elemental or world-specific abilities and team coordination.

World rules may disable or radically alter combat.

## 14. Taijifu integration

Taijifu is the official martial art of HNK.

HNK-VERSE should therefore treat Taijifu as a privileged canonical martial bridge, not as a generic fantasy skill invented inside the game.

Architecture:

HNK-VERSE MARTIAL RUNTIME → TAIJIFU_BRIDGE → VERSIONED TAIJIFU CANON

HNK-VERSE may provide Taijifu learning content, dojo spaces, Masters, techniques, training, sparring, combat application, simulations, evidence collection and practice history.

But:

HNK-VERSE XP ≠ OFFICIAL TAIJIFU BELT

GAME COMPLETION ≠ OFFICIAL GRADUATION

Official belt/promotion authority remains in Taijifu Platform and its authorized evaluation model.

## 15. Combat mastery

Martial capability should use actual performance evidence.

Examples include recognizing an incoming technique, selecting a valid response, defending successfully, reproducing a technique, executing under changed context, adapting timing/positioning and completing mentor trials.

A combat animation playing does not prove mastery.

## 16. Alchemy

Alchemy in HNK-VERSE should inherit Athanor + Crônicas property/process thinking.

MATERIAL → PROPERTIES → PROCESS → TRANSFORMATION → RESULT → OBSERVATION → RECORD

Alchemy should support known procedures, experimental procedures, failure, partial success, discovery and symbolic/metaphysical correspondence where canonically defined.

It must not collapse every transformation into recipe ID lookup.

## 17. Technology and engineering

Dr. Stone reference + Tehkné Studio + AFTERWORLD provide the design basis:

KNOWLEDGE → MATERIAL → TOOL → PROCESS → COMPONENT → SYSTEM → INFRASTRUCTURE → NEW CAPABILITY

Engineering creation may use components, properties, compatible ports, capabilities, relationships, behaviors and automation.

Technology can therefore progress by genuine dependency chains rather than abstract tech-tree purchases alone.

## 18. Magic / metaphysical capability

HNK-VERSE may model magical/metaphysical actions where HNK canon defines them.

The game layer must keep separate canonical symbolic/metaphysical relationship, executable game effect, user experience, interpretation and evidence.

Therefore:

GAME MAGIC EFFECT ≠ SCIENTIFIC PROOF OF METAPHYSICAL CLAIM

A capability may require:

KNOWLEDGE + LANGUAGE + SYMBOL + PRACTICE + TOOL/OBJECT + WORLD CONDITION + PERMISSION

depending on the HNK system being represented.

## 19. Perception and appraisal as RPG capability

Kanteishi/Appraiser + Crônicas strongly support perception as a progression domain.

A skilled Persona may perceive hidden object properties, material quality, provenance, language layers, creature signs, structural weakness, anomaly conditions, social clues or symbolic correspondences.

Perception must reveal data justified by capability and world state, not arbitrary omniscient UI.

## 20. Research and investigation

Research becomes playable progression.

QUESTION → OBSERVATION → CLAIM → EVIDENCE → COMPARISON → EXPERIMENT → CONCLUSION → NEW CAPABILITY

Crônicas already provides internal domain evidence for this model.

Knowledge may remain uncertain, contested or contradicted.

The game should allow useful action under uncertainty without pretending uncertainty has disappeared.

## 21. Creatures

Creature progression should not reduce to combat level.

Potential dimensions include bond, trust, learned behavior, ecology knowledge, work capability, exploration ability, communication, training, health/needs, social structure and inherited traits where world rules permit.

AFTERWORLD already provides creature learning/culture/social/generation concepts.

Pokémon and Palworld remain external design references, not canonical templates.

## 22. Equipment and tools

Equipment should express capability and context, not merely stat escalation.

An item may provide a new action, better efficiency, access to material/process, protection, information/perception, storage, movement, social/institutional permission or connection to other systems.

Higher rarity does not automatically mean universally better.

## 23. Failure

Failure must be meaningful and informative.

Candidate outcomes include no progress, partial progress, resource loss, tool wear, injury/defeat according to world rules, new information, relationship consequence, anomaly consequence, alternative solution or mentor feedback.

Failure should not always mean punishment.

A failed experiment may generate valuable evidence.

## 24. Difficulty

Difficulty should come from system demands, not only inflated HP.

Candidate dimensions:

- complexity;
- timing;
- resource scarcity;
- environmental risk;
- incomplete knowledge;
- social resistance;
- evidence requirements;
- coordination;
- precision;
- world-law constraints;
- adversary capability.

## 25. Progression gates

An advanced capability may require combinations of:

KNOWLEDGE + SKILL EVIDENCE + RELATIONSHIP / MENTOR ACCESS + RESOURCE + TOOL + LANGUAGE + INSTITUTION + WORLD CONDITION + PERMISSION + PREREQUISITE CAPABILITY

This replaces simplistic level-only gates.

## 26. Sephirotic meta-progression

The Sephirotic Tree remains the deep HNK-VERSE meta-architecture already locked in D003.

RPG systems may expose local skill trees, profession paths or world-specific progressions.

These local systems do not replace the deeper HNK structure.

LOCAL RPG PROGRESSION ≠ HNK META-PROGRESSION

The initial executable layer remains Malkuth.

Specific Sephirotic gameplay mappings should consume approved CODEX-HNK canon rather than be invented inside this Discovery.

## 27. Rewards

Rewards may include knowledge, access, relationship, resource, tool, capability, recipe/process, profession recognition, territory permission, institutional role, world authority, cosmetic identity, Chronicle entry and XP summary.

Money and combat gear are not the only reward classes.

## 28. Player build identity

The player build is emergent:

BUILD = KNOWLEDGE + LANGUAGE + SKILLS + PROFESSIONS + RELATIONSHIPS + EQUIPMENT + CREATURE BONDS + AUTHORITY + WORLD HISTORY

Two players with similar numeric XP may therefore be radically different.

## 29. Respec and experimentation

Because the system is practice-based rather than class-locked:

- learning a new domain should usually be possible;
- historical mastery should not disappear because another path is chosen;
- local world rules may limit simultaneous equipment/active abilities;
- specialization may increase efficiency without permanently deleting alternatives.

## 30. Presentation independence

Gameplay truth must remain independent from animation and VFX.

Taijifu Masters Assets and Alakazam Strangeverse support:

DOMAIN ACTION → GAMEPLAY STATE → RUNTIME MAP → ASSET

not:

ASSET PLAYED → THEREFORE ACTION SUCCEEDED

This is critical for deterministic tests and future visual upgrades.

## 31. Agent and AI participation

Agents may mentor, train, learn, practice, gain professions, fight, craft, research, form hypotheses, teach, govern and fail.

But Agent progression must use bounded world rules and authoritative domain commands.

Agent claims about mastery are not mastery evidence by themselves.

## 32. ZERO RPG + Mastery proof

ZERO should prove only:

1. one discoverable knowledge item exists;
2. the avatar can perceive/learn it;
3. knowledge unlocks one possible action;
4. the avatar performs one practice action;
5. an authoritative event records the attempt;
6. success/failure is evaluated from world/domain rules;
7. the event contributes evidence to one skill;
8. skill state changes based on evidence;
9. XP may summarize the progress without being the sole authority;
10. one Mentor/Agent can react to the demonstrated state;
11. one profession candidate can begin emerging from repeated activity;
12. one optional challenge can use the skill;
13. gameplay outcome persists across logout/login;
14. presentation/animation remains a projection of domain state.

No full class system, full combat tree, full dungeon system or full Taijifu curriculum is required for ZERO.

## 33. Locked decisions

1. HNK-VERSE uses practice-based, capability-oriented progression rather than mandatory starting classes.
2. Knowledge, skill, profession, relationship, authority and manifestation are distinct progression layers.
3. XP is feedback/projection, not the sole proof of mastery.
4. Skill mastery must be able to reference authoritative gameplay evidence.
5. The generic mastery principle follows encounter → recognition → understanding → practice → reproduction → application → adaptation → mastery, with domain-specific variations allowed.
6. Professions emerge from mastery clusters.
7. Mentors/Masters teach, observe and evaluate rather than functioning as simple skill shops.
8. Quests should resolve from authoritative world events when possible.
9. Adventure/dungeon gameplay is a complementary loop, not the entire game.
10. Combat is first-class but optional as a specialization.
11. Taijifu is the official HNK martial bridge; game XP cannot grant official Taijifu graduation.
12. Alchemy uses properties/processes/experimentation rather than recipe IDs alone.
13. Technology progresses through knowledge/material/tool/process/component/system dependencies.
14. Magical/metaphysical gameplay must preserve the Lucidity separation between game effect, metaphysical correspondence, experience, interpretation and evidence.
15. Perception/appraisal/research are first-class RPG capabilities.
16. Creature progression includes bond, ecology, learning and work roles beyond combat.
17. Failure may produce information and progression evidence rather than only punishment.
18. Advanced gates may combine knowledge, evidence, relationship, resource, tool, language, institution, world condition and permission.
19. Sephirotic progression remains deep meta-architecture and consumes approved HNK canon.
20. Gameplay state remains independent from presentation assets.
21. Agents use the same bounded mastery and command architecture rather than privileged progression shortcuts.
